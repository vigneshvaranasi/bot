Incident ID: PAYU-INC-2025-05-21-512
==================================================

Impact:
- Summary:
  - Approximately 152 payment initiation requests failed due to premature client-side disconnections.
  - The client experienced a drop in successful transactions during their flash sale event.
  - No PayU infrastructure or services were impacted.
- Impacted Transactions:
  - Count: 152
  - Details: All failed requests were for the 'Create Transaction' endpoint from the client's primary integration.

PSDII Reportable:
- Status: false
- Reason: The issue was client-side; no PayU service unavailability or data compromise occurred.

Impacted Application: Client's E-commerce Backend

Accountable Party:
- Entity: Client-side Integration
- Details: Client's internal timeout configuration was not robust enough to handle standard payment processing latency variations.

Repeat Incident:
- Status: false
- Details: First reported instance of this issue from this client.

Root Cause:
- Client application prematurely closed HTTP connections.
- Root cause was identified as a client-side load balancer timeout set to 3 seconds, which is below the recommended threshold for payment processing.

Mitigation:
- PayU Actions: No changes were required on the PayU platform.
- Client Recommendations:
  - Advised client to increase their API call timeout to a minimum of 10 seconds.
  - Recommended implementing an exponential backoff retry mechanism for 499 errors and network-level timeouts.

Timeline:

- [14:35 - 14:55] - L2 Engineering initiated investigation, analyzing API gateway logs and Kibana dashboards.

Impact:
- Summary:
  - Three clients experienced intermittent HTTP 403 (Forbidden) errors for a period of 2 hours.
  - An estimated 50-100 legitimate transactions were blocked.
  - Security systems successfully prevented any fraudulent transactions from being processed.
- Impacted Transactions:
  - Count: 100
  - Details: Legitimate transactions were blocked as collateral damage from security measures.

Impacted Application: PayU Security Infrastructure (WAF)

Accountable Party:
- Entity: External Attackers
- Details: The incident was triggered by a malicious carding attack. The impact to legitimate clients was an unintended consequence of the defensive measures.

Repeat Incident:
- Status: false
- Details: While attacks are common, this specific pattern of collateral damage is rare.

Root Cause:
- A large-scale, distributed carding attack forced automated security rules to block offending IP ranges.
- A few legitimate clients were using a shared IP address that was part of the blocked range, causing them to be flagged as malicious.

Mitigation:
- PayU Actions:
  - The Security Operations Center (SOC) analyzed the traffic and identified the impacted clients.

  - The blocking rule was refined to be more specific to the attacker's signature, reducing the chance of false positives.

  - Recommended they use a dedicated static IP for their API traffic to prevent future issues with shared proxies.

- [02:45 - 03:30] - SOC investigated the client's traffic, confirmed it was a false positive, and identified their shared IP.
- [03:45] - Client's IP was added to an allow-list, resolving their issue. Rules were refined.

Problem Records:
- Created: true
- Reason: Problem record PRB-2025-130 was created to explore more sophisticated client identification methods beyond IP addresses to reduce false positives during attacks.
